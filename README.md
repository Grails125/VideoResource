在客户端进入“设置 → 站源管理 → 添加 → 配置订阅”，选择分类或填写上表地址，读取预览后确认导入。首次导入只新增，更新已有配置需要检查差异并确认；个人停用、账号权限及观看下载资料由客户端管理。

四份订阅使用 `cache_time: 7200` 与 `api_site` 外层结构。普通采集接口使用公开 HTTP／HTTPS 地址，可选原生来源使用客户端支持的稳定适配器及 `native.version=1`。客户端内置来源不应再次导入。

## 维护规则

- 固定使用影视、短剧、动漫、未知四类，仓库中只保留上表四份 JSON，不新增合集、索引或归档 JSON（包括 `404.json`）。移除的来源从 Git 历史追溯；内容范围待确认的来源保留在未知类。
- 新增项按稳定键、适配器及规范化接口地址与独立详情配置去重，追加到对应文件末尾，保留既有身份和顺序；不按名称合并接口。
- URL 只统一主机大小写、默认端口、末尾斜线和 `ac=list`，保留其他查询、转义路径、协议和独立详情配置。
- 显示名保留站名、真实数字及英文大小写，移除装饰、测速延迟与批次标签，不增加“成人 ”前缀；同名不同接口只报告，不自动改名。
- 所有发布配置默认启用，健康检查失败不自动禁用；已安装的个人停用选择由客户端保留。
- 不提交账号、Cookie、密钥、个人配置、媒体或图片正文，不绕过 TLS、登录、付费、DRM 或访问拒绝。

完整约束见 [AGENTS.md](AGENTS.md)。原有内容更新、迁类或协议变化应有明确任务依据，不以检测失败改写来源。

## 离线校验

python -B scripts/check_subscriptions.py
python -B scripts/test_check_subscriptions.py
python -B scripts/test_check_health.py

校验范围包括四份 JSON、结构与字段、动态分类数量、256 项单文档上限、稳定键及接口去重、名称、公开地址、适配器身份与默认启用。合成回归不访问真实来源；原生检测器另使用固定客户端核心验证配置与协议闭环。

## 在线健康检测

[手动运行与结果](https://github.com/yingchuan-media/yingchuan-sources/actions/workflows/source-health.yml)。计划每天 **06:17（UTC+8）**运行，GitHub 可能排队延迟。仅默认分支运行可更新下方自动区；其他分支手动运行只提供摘要和 artifact，不写回默认分支。

| 项目 | 检查范围 |
| --- | --- |
| 目录 | 每站第一页的第一条有效记录，校验实际身份与非空列表 |
| 封面 | 仅 HEAD 状态和 Content-Type，不读取或解码图片正文 |
| 搜索 | 抽样片名与媒体身份匹配，本地有界搜索明确标注 |
| 播放 | 第一条线路的第一集，有界媒体样本与首帧尝试；不支持或需授权时标为未验证 |
| 延迟 | 当前运行节点的单次请求耗时，包含 DNS、TLS 与读取；不是用户设备延迟或吞吐量 |

原生来源通过固定客户端核心调用实际协议，逐站使用空目录和独立进程。FFmpeg 下载与二进制身份均固定校验。检测 job 只读，文档更新在独立 job 执行；报告仅显示名称、稳定键、时间、工具版本和结果，不保存片名、图片或媒体地址及响应正文。

维护者需在 Actions Secrets 配置 `NATIVE_CLIENT_REPOSITORY` 和 `NATIVE_CLIENT_READ_TOKEN`，后者仅需固定客户端仓库的 Contents 只读权限。工作流只检出指定提交的 `native/`，随后移入 runner 临时目录，凭据不持久化，源码不进入公开报告和缓存。缺少凭据时会在检出前明确停止。

待检测、失败和未验证都不等于来源被禁用；离线校验、单条样本可播和完整来源／设备验收分别报告。下表由脚本原子生成，手动维护时保留自动区标记与原始结果。
