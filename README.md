## 使用

在映川「设置 → 站源管理 → 添加 → 配置订阅」选择分类，或填写对应地址；读取预览后确认导入。更新已有配置时检查差异并明确确认，个人停用选择、来源身份、权限与观看下载资料由客户端管理。

四份订阅统一使用 `cache_time: 7200` 与 `api_site` 外层结构。普通采集接口使用 HTTP／HTTPS；原生来源通过客户端已支持的稳定适配器接入，使用 `native.version: 1`。B站、红果、影视、影视2、奈飞已内置于客户端，不在本仓库发布或检测。不同接口但名称相似的来源保留各自身份。

## 维护与校验

- 每个稳定来源键及接口身份只在一份订阅中维护。新增前检查键、适配器或规范化接口地址与独立详情配置，去重后追加到对应文件末尾；保留其他条目的内容和顺序。
- URL 去重仅统一主机大小写、默认端口、末尾斜线和 `ac=list`，保留其他查询参数、转义路径、HTTP／HTTPS 及独立详情配置。
- 来源显示名保留站名文字、真实数字和英文大小写，移除装饰符号及测速延迟；有意义的括号内容转为普通文字。未知分类不添加“成人 ”名称前缀，既有分类和来源身份保留。校验器拒绝再次混入前缀、装饰或延迟，只报告同名来源，不按名称合并接口或自动改名。
- 所有发布来源默认启用；检查失败只记录结果，不自动禁用来源。不提交账号、Cookie、密钥、个人配置、媒体或站源图片。
- 不新增其他 JSON 文件。数量、名称、顺序和检测条目只从当前四份 JSON 读取；下一次成功检测自动替换 README 的订阅统计与逐站表格，增加新项、移除撤下项，不维护固定数量断言。每份文档仍限制 256 项并逐条校验与去重；旧内容需要追溯时查看 Git 历史。

在仓库根目录执行：

```sh
python -B scripts/check_subscriptions.py
python -B scripts/test_check_subscriptions.py
python -B -m unittest discover -s scripts -p 'test_*.py'
```

校验器检查仅有四份订阅 JSON、外层结构与字段类型、文档容量、稳定键和接口去重、显示名格式、公开 HTTP／HTTPS 地址、原生适配器身份及版本、默认启用状态及禁止重新收录内置适配器，并报告同名来源。来源数随文档实际内容统计，不要求维护脚本中的固定数量。

这些检查不请求站源图片、账号或媒体，也不等同于当前站点可用性、真实播放、完整原生配置行为或物理设备验收；来源访问条件仍由对应服务决定，不绕过 TLS、登录、付费、DRM 或访问拒绝。

## 每日在线检测

[检测工作流与网页手动运行入口](https://github.com/yingchuan-media/yingchuan-sources/actions/workflows/source-health.yml)。工作流进入默认分支后，计划每天 **06:17（香港时间，UTC+8）**运行；GitHub 定时任务可能排队延迟，公开仓库长期无活动时也可能停用计划。拥有仓库写入权限的维护者可打开该页面，点击 **Run workflow**，选择默认分支再运行。其他分支的手动运行只生成运行摘要和报告 artifact，不写回默认分支。

脚本使用 Python 3.12+ 标准库；本地首帧检测和合成首帧回归另需 PATH 中的 FFmpeg。工作流在隔离的只读检测 job 中准备固定的 Linux x64 FFmpeg，记录其实际构建版本。测试只使用合成元数据和合成媒体，不访问站源。在线阶段每站只抽样目录第一页的第一条有效记录：

- **目录**：标准接口请求 JSON／XML 采集列表；原生接口调用客户端真实目录协议，均校验媒体身份与非空列表。保留接口中其他有语义的查询参数及转义路径。
- **封面**：仅向抽样记录的封面地址发送 HEAD，核对状态及图片 Content-Type；不发送 GET、不读取图片正文、不验证图片解码。拒绝 HEAD 或返回封装类型时不能证明图片无效。
- **搜索**：以抽样片名搜索，要求匹配媒体身份。原生源调用客户端对应搜索入口；客户端只有有界本地搜索时准确标明本地匹配，不冒充服务端搜索。只检查一次查询，不测试全量分页。
- **能否播放**：选第一条线路的第一集，探测实际响应；HLS 最多解析三层，仅读一个完整片段入口和必要 init，单个媒体样本最多 1 MiB，以只允许 pipe 输入的 FFmpeg 尝试解码一个视频帧。网页解析、DASH、加密或字节范围 HLS 标为未验证；不获取授权、Cookie、密钥或其他线路。
- **延迟**：目录列为目录阶段耗时，其他检查单列耗时。标准接口为单次请求读取；原生源包含客户端必要的协议封包、请求与解析。包含 DNS、连接、TLS 及有界正文读取，不是 ICMP ping、吞吐量、平均值或用户设备测量；失败耗时仍保留并标明失败。

所有 JSON 中的标准接口和可选原生接口都进入检测。原生程序以 [客户端核心 3b1d9b0](https://github.com/yingchuan-media/yingchuan/tree/3b1d9b0e2e096203cba6156b3aee241033ca4823/native)及本仓库 `scripts/native_probe_test.go` 编译，执行客户端配置校验、目录、搜索、详情、取流和有界首帧解码，保留签名、封包、WASM 沙箱、媒体凭据与访问边界。每站为独立进程及一次性空资料目录，不读取本人账号或已安装客户端资料，不代登录或确认受限访问。需要本人授权、加密／DASH 或超出有界样本能力时逐步记录原因；原生程序缺失或进程结果不完整会使工作流失败并保留旧报告，不再把所有原生源统一跳过。

目录不可用时，后续依赖项标为未检测。首帧未解码只说明本次有界抽样失败，可能受片段大小、MP4 索引位置、地域或运行节点访问条件影响，不自动判定全站失效。当前清单、分类数量与显示名每次从 JSON 重建，成功提交时会清除已移除来源的旧检测行。

默认最多 6 站并行。标准接口每请求 8 秒、每站网络阶段 50 秒及 16 次请求预算；原生流程上下文最多 70 秒、每站 64 个 HTTP 请求，进程另限 85 秒，沿客户端自身的有界请求重试规则执行；首帧解码最多 10 秒。工作流另设 35 分钟总上限。公网 DNS 结果固定到连接，媒体和重定向校验私网地址及 HTTPS 降级，不破解挑战、不切换到未选媒体线路。响应正文、媒体样本只留进程内存，不写入仓库或 artifact。检测失败只更新结果，不修改订阅、排序、名称或启停状态。任务执行错误不会覆盖上次报告。

只有当前 JSON 含原生配置时，工作流才准备 Go 1.24.1、拉取固定客户端修订的 `native/` 源码并构建检测器，运行 Go 合成协议闭环及逐订阅客户端解析验证。只缓存公开 Go 模块，并执行 `go mod verify`；客户端源码、资料和检测器产物不写入本站源仓库或报告 artifact。Go 核心和标准接口均由同一 README 汇总结果。

Ubuntu 24.04 x64 的解码工具准备统一由 `scripts/setup_ffmpeg.py` 维护，整个步骤最多 5 分钟，使用 [imageio-ffmpeg 0.8.1](https://github.com/imageio/imageio-ffmpeg/releases/tag/v0.8.1) 的 `manylinux_2_28_x86_64` wheel 中的独立二进制。实际构建固定为 `n9.0.2-17-g2a571b6068-20260930`，属于 FFmpeg 9.0.2 发行分支构建；这是 CI 命令行工具，不是客户端 FFmpeg 库集成。包 SHA-256 固定为 `050d6850601c3b3890bd2b28306f3b842b3daea390a561101174375a1c460bda`，可执行文件 SHA-256 固定为 `0d709a0bed1a43f24cd2c420878c63afea4580671b6949ad19ed124572f3bc3d`；[上游二进制来源与校验记录](https://github.com/imageio/imageio-ffmpeg/blob/v0.8.1/tools/ffmpeg-sources.json)可供核对。FFmpeg 使用 GPLv3+，imageio 包许可证为 BSD-2-Clause，运行目录保留两者许可证及源代码链接。

缓存只保存原始公开 wheel，以完整包摘要作为键；每次恢复重新校验包和二进制，校验失败立即停止。无缓存时通过 pip 从固定的 PyPI 文件 URL 下载，失败后最多尝试一次 GitHub 上相同摘要的同一发布包；每个地址总计最多 120 秒、连接／读取超时 15 秒，不读取包索引、安装额外依赖或自动选择新版。只提取明确的二进制及许可证，不导入或安装 imageio Python 包。版本核验限 10 秒，通过后才写入 `GITHUB_PATH`。该路径无需 APT、sudo、Ubuntu 软件源或 DNS 配置修改；下载及验证失败保留原报告。损坏缓存须清除对应 Actions cache 后重试。

检测 job 只有只读权限且不保留 Git 凭据，随后独立 job 用 `GITHUB_TOKEN` 的 `contents: write` 仅提交 README。分支保护若禁止机器人直接提交，或检测期间默认分支发生变化，写回会失败并保留运行摘要与 7 天 artifact，不强推、不覆盖人工修改。仓库或组织必须允许工作流所需的写入权限；不需要个人令牌或新增 Secrets。
